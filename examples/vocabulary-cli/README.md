# Vocabulary CLI example

English | [简体中文](README.zh-CN.md)

This private workspace is a runnable consumer of all three Alstate packages. It
shows where an application model and interaction flow sit around the headless
engine. It is not published, and none of its vocabulary schema or CLI behavior
is part of Alstate's public API.

## What the example demonstrates

- composing `LearningEngine`, `SqliteLearningStore` and `FsrsAlgorithm`;
- keeping vocabulary fields in opaque application item data;
- parsing stored JSON before using domain fields;
- adding, reading, replacing and deleting items;
- building a due queue, committing a rating and reading review history;
- adapting a JSON import file outside the engine.

```text
src/app/create-app.ts                  composition root
src/cli/run-cli.ts                     command handling
src/domain/vocabulary-item.ts          vocabulary data and validation
src/infrastructure/read-import-file.ts JSON input adapter
src/main.ts                            executable entry point
```

## Run

From the repository root:

```bash
npm install
npm run example:vocabulary -- help
```

The first command builds every workspace before starting the CLI. Data defaults
to `.alstate/vocabulary-example.db`. Override it for an isolated run:

```powershell
$env:ALSTATE_VOCABULARY_DB_PATH = "data/my-vocabulary.db"
npm run example:vocabulary -- item:add bank
```

## Commands

| Command | Purpose |
| --- | --- |
| `item:add <word>` | Create a vocabulary item, initially due now. |
| `item:list [word]` | List all items, or filter by exact word. |
| `item:show <item-id>` | Show one parsed vocabulary item. |
| `item:delete <item-id>` | Delete an item, state and history. |
| `meaning:add <item-id> <english\|chinese> <meaning>` | Append a meaning by replacing item data. |
| `note:add <item-id> <note>` | Append a note by replacing item data. |
| `import <json-file>` | Validate and add records from a JSON array. |
| `review [again\|hard\|good\|easy]` | Review the earliest due item; prompt when rating is omitted. |
| `history <item-id>` | Print the item's review records. |

A complete non-interactive workflow:

```bash
npm run example:vocabulary -- item:add bank
npm run example:vocabulary -- meaning:add 1 english "a financial institution"
npm run example:vocabulary -- meaning:add 1 chinese "银行"
npm run example:vocabulary -- note:add 1 "Common noun"
npm run example:vocabulary -- item:show 1
npm run example:vocabulary -- review good
npm run example:vocabulary -- history 1
```

IDs are generated by SQLite, so use the ID printed by `item:add` rather than
assuming it is `1`.

## Import format

`import` accepts a JSON array. `word` is required. Meaning, note and tag
arrays are optional; missing arrays default to empty.

```json
[
  {
    "word": "bank",
    "englishMeanings": ["a financial institution"],
    "chineseMeanings": ["银行"],
    "notes": ["Common noun"],
    "tags": ["CET6"]
  }
]
```

The import adapter intentionally supports only fields needed by this example.
Audio and example-sentence data exist in the domain model but are not exposed as
CLI editing commands.

## Application boundaries visible here

`createVocabularyApp` is the composition root and is the only place choosing
FSRS and SQLite. The domain parser owns vocabulary validation. The CLI owns
argument parsing, exact-word filtering, rating input and output formatting.
Alstate sees only JSON item data and scheduling operations.

The example reviews the first item returned by `engine.due(new Date(), 1)`. A
real application can build a different queue policy, but should still commit the
selected rating through `engine.review()`.
